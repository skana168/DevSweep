# GPUI UI 迁移

设计与任务拆分已确认，用户已通过 implement-spec 授权进入实现。

## 已确定

- 完整迁移至 GPUI Kit，保留产品能力与持久化数据兼容，允许重新设计布局和交互。
- 遵循 GPUI Kit Design Guides 与 Coding Guides，方向为原生、克制、高效。
- macOS、Windows 同等验收；本轮不扩展 Linux 产品支持。
- 开发期间保留 egui 对照，完成 GPUI 验收后切换，最终仅维护一个前端。
- 保留清理预览、确认、执行前重检、中止、失败反馈及任务排队安全语义。
- 保留品牌资产，以 GPUI Kit 主题、组件几何和平台字体策略替代旧 Craft 主题规范。

架构决策见 [ADR-0003](../../docs/adr/0003-migrate-ui-to-gpui-kit.md)。领域用语沿用根目录 GLOSSARY.md，不将 Project size 混称为可释放体积。

## 界面结构

- 左侧为项目 / 全局缓存导航；扫描根和项目类型筛选放入所属视图，区分全局导航与局部筛选。
- 项目列表为主工作区，选中项目后在可调整宽度的右侧面板展示清理项、体积与风险，保留列表上下文。
- 支持跨项目勾选；底部固定显示选择范围、已选体积和清理入口。
- 确认时展示清理计划与删除方式；项目大小与已选体积保持不同语义。
- GPUI 前端统一使用 Kit 自带图标；迁移期间 egui 使用 egui_icons。对应约定已更新至 AGENTS.md。

## 设置与交互

- 保留中文 / 英文、跟随系统 / 浅色 / 深色、默认删除方式及窗口尺寸记忆，沿用现有配置文件；设置采用独立对话框。
- 支持列表方向键导航、空格勾选、刷新与打开设置的快捷键，按平台使用 Command / Control 约定。
- Escape 关闭最上层可关闭浮层并恢复焦点；清理快捷键仍进入计划确认，不绕过确认。
- 扫描、测量、清理在后台执行，界面保持响应；显示真实进度与中止状态，明确区分请求中止和已经停止。
- 失败详情支持查看与复制。

## 验收与切换

- 保留并通过现有业务测试；将依赖 egui 的交互覆盖迁移为 GPUI 核心 UI integration tests。
- 在 macOS、Windows 验证扫描、筛选、勾选、计划确认、清理、中止、失败恢复的完整流程。
- 验证主题、语言、窗口缩放、键盘导航和焦点恢复；未实际验证的平台明确标记，不视为通过。
- 达到上述条件后才移除 egui，最终只维护 GPUI 前端。

## 实现顺序

遇到不熟悉或不确定的 GPUI 用法时，查阅已安装的 skills：[gpui-kit](../../.agents/skills/gpui-kit/SKILL.md) 用于组件 API、状态、事件、异步任务与测试；[gpui-kit-design-guides](../../.agents/skills/gpui-kit-design-guides/SKILL.md) 用于布局、视觉层级、主题、交互状态及界面文案。按 skill 指引读取相关指南与参考资料，并以当前依赖版本的源码核实 API。

1. 核实并锁定 GPUI Kit 依赖，搭建窗口、主题、字体、图标与配置适配，保留 egui 对照入口。
2. 接入既有扫描、测量、刷新业务，完成项目 / 全局缓存导航、列表、筛选和右侧清理面板。
3. 接入清理计划确认、执行、中止、进度和失败详情，保持既有安全与排队语义。
4. 完成设置、键盘操作、焦点和各类空白 / 加载 / 失败状态，运行自动化与双平台流程验收。
5. 验收通过后切换默认入口并删除 egui 前端与失效依赖。

以上为已逐轮确认的设计范围。具体 API、模块拆分、控件尺寸与测试用例由实现依据现有代码及 GPUI Kit 指南确定。测试边界为既有业务公开接口、配置兼容接口及真实 GPUI 组件交互，验收要求见各票据。
